# Telegram-бизнес-ассистент

Переиспользуемый, готовый к продакшену шаблон Telegram-бота для поддержки
клиентов. Каждое развёртывание настраивается под конкретный бизнес через
Markdown-файл базы знаний (`data/business.md`) и отвечает на вопросы
клиентов с помощью OpenAI Responses API, строго опираясь на содержимое
этого файла. Работает как stateless-приложение на FastAPI в Vercel,
полностью управляется через Telegram-webhook.

## 1. Обзор проекта

- Клиенты задают вопросы в Telegram; бот отвечает, используя только
  информацию из `data/business.md`.
- Когда ИИ не уверен в ответе или информации не хватает, бот честно
  сообщает об этом и предлагает оставить контактные данные для связи с
  человеком (создаётся "заявка"/lead).
- Зарегистрированный администратор получает в Telegram каждую
  эскалированную заявку, может ответить через бота и отметить заявку как
  решённую.
- Всё состояние (диалоги, заявки, шаг FSM, дедупликация) хранится в
  Postgres, а не в памяти процесса, поскольку serverless-функции не имеют
  состояния (stateless).

## 2. Архитектура

```
Telegram  --webhook-->  Vercel (FastAPI, api/index.py -> app.py)
                              |
                              v
                     bot/router.py (диспетчеризация)
                     /        |         \
        bot/handlers/*   services/*   database/repositories/*
                              |
                     OpenAI Responses API   Postgres (async, SQLAlchemy)
```

- **api/index.py** — точка входа Python для Vercel; просто реэкспортирует
  FastAPI-приложение `app` из `app.py`.
- **app.py** — FastAPI-приложение: `GET /`, `GET /health`, `POST
  /api/telegram/webhook`. Вся обработка webhook выполняется синхронно
  (через `await`) до того, как отправляется HTTP-ответ (Vercel не
  гарантирует продолжение фоновой работы после ответа).
- **bot/** — диспетчеризация обновлений (`router.py`), обработчики
  команд/callback-ов, инлайн-клавиатуры и константы состояний FSM.
  "Состояние" диалога (например, "собираем номер телефона клиента")
  хранится в строке таблицы `users` (`fsm_state` / `fsm_data`), а не в
  памяти — потому что "тёплый" экземпляр Vercel может не получить
  следующее обновление от того же пользователя.
- **services/** — `knowledge_service.py` (загрузка/кэширование
  `business.md`), `openai_service.py` (Responses API + валидация
  структурированного вывода), `telegram_service.py` (прямые вызовы Bot API
  через `httpx`, без polling/фреймворка), `escalation_service.py`
  (создание заявки + уведомление администратора), `validation.py`
  (проверка имени/телефона/email).
- **database/** — асинхронные модели и репозитории SQLAlchemy. В
  продакшене — Postgres, в тестах — SQLite (aiosqlite).

Интеграция с Telegram реализована через прямые вызовы `httpx`, а не через
фреймворк на основе polling (например, диспетчер aiogram), потому что
polling явно не поддерживается на Vercel, а встроенное хранилище FSM в
таких фреймворках обычно рассчитано на долгоживущую память процесса,
которой в serverless-среде нет.

## 3. Локальная установка

### Версия Python

Python 3.11 или 3.12.

### Установка

  ```bash
  python -m venv .venv
  source .venv/bin/activate   # Windows: .venv\Scripts\activate
  pip install -r requirements-dev.txt
  cp .env.example .env
  ```

Заполните `.env` реальными значениями (см. раздел 5).

## 4. Переменные окружения

Полный список с описаниями — в `.env.example`. Обязательные:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `OPENAI_API_KEY`,
`DATABASE_URL`. Все остальные имеют безопасное значение по умолчанию или
опциональны (`ADMIN_SETUP_SECRET` / `ADMIN_TELEGRAM_ID` управляют
регистрацией администратора — см. раздел 12).

Никогда не коммитьте `.env`. Он уже исключён через `.gitignore`.

## 5. Настройка базы данных

Подойдёт любой экземпляр Postgres; настоятельно рекомендуется провайдер с
пулингом соединений (Neon, Supabase или RDS Proxy), поскольку
serverless-функции открывают много коротких соединений (по этой же причине
на стороне Python используется `NullPool` — соединения не удерживаются
открытыми между вызовами).

Быстрый старт (только для разработки, см. ограничения ниже):

```bash
python scripts/init_db.py
```

Для продакшена / любых изменений схемы после первого запуска — используйте
Alembic:

```bash
alembic upgrade head
```

`scripts/init_db.py` просто вызывает `Base.metadata.create_all`: у него нет
истории миграций, и он не изменит таблицу, которая уже существует. После
первого запуска используйте Alembic (`alembic revision --autogenerate -m
"..."`, затем `alembic upgrade head`) для любых последующих изменений
схемы.

## 6. Редактирование `data/business.md`

Этот файл — вся база знаний бота, он целиком отправляется модели при
каждом вопросе (с учётом ограничения `MAX_KNOWLEDGE_CHARACTERS`, по
умолчанию 80 000 символов). Структурируйте его чёткими Markdown-заголовками
— см. пример из поставки для ожидаемых разделов (товары/цены, доставка,
оплата, часы работы, адрес/контакты, FAQ, возврат/гарантия).

- Следите за точностью: модели дана инструкция отвечать *только* на
  основании этого файла и эскалировать вопрос, а не додумывать, если
  чего-то не хватает.
- На Vercel файл упаковывается в развёртывание на этапе сборки, поэтому
  его редактирование требует повторного деплоя — `/reload` (только для
  администратора) заново валидирует и пересчитывает хэш кэша в памяти, но
  не может подтянуть содержимое, которое Vercel не упаковал.
- Если ваша база знаний превысит `MAX_KNOWLEDGE_CHARACTERS`, этот шаблон
  откажется отвечать с её использованием (безопасный отказ), а не станет
  молча обрезать информацию о бизнесе. В этом случае добавьте retrieval
  (RAG): интерфейс `KnowledgeService` (`services/knowledge_service.py`)
  намеренно небольшой, чтобы его можно было заменить на векторное
  хранилище или ретривер на основе БД без изменения вызывающего кода.

### Структурированный каталог товаров

В `data/business.md` также есть таблица `## Structured Product Catalog`.
Это **единственный** список товаров, которые бот может рекомендовать; он
разбирается программно в `services/catalog_service.py`:

| Колонка | Значение |
|---|---|
| `product_id` | Стабильный ID, который использует модель; не переименовывайте существующие |
| `Назва` | Отображаемое название для покупателя |
| `Ціна` | Подтверждённая цена в гривнах, либо `невідомо` |
| `Наявність` | `в наявності`, либо `невідомо`, если наличие не подтверждено |
| `Категорія`, `Теги` | Используются для подбора товаров под запрос |

Чтобы добавить или изменить товар, редактируйте эту таблицу, а не промпт.
Цены и наличие, которые видит покупатель, всегда берутся отсюда, а любой
выдуманный моделью товар отбрасывается до отправки ответа.

## 6a. Язык интерфейса и рекомендации

Интерфейс для покупателей — **украинский по умолчанию**, и бот отвечает
по-украински, даже если покупатель пишет на другом языке. Все тексты для
покупателей находятся в `bot/locales/uk.py` и подставляются через `t("key")` —
не хардкодьте видимые покупателю строки в обработчиках. Чтобы добавить
локаль, создайте модуль в `bot/locales/` и зарегистрируйте его в `LOCALES`;
украинский остаётся фолбэком для отсутствующих ключей.

Ассистент работает с двумя источниками разного уровня доверия:

- **Факты о бизнесе** (товары, цены, наличие, доставка, оплата, контакты,
  состав, аллергены, акции, правила) берутся *только* из `data/business.md`
  и никогда не генерируются.
- **Кулинарные рекомендации** (сочетания вкусов и текстур, идеи подачи,
  пары к чаю/кофе, концепции подарочных наборов) могут использовать общие
  знания модели и подаются покупателю именно как рекомендации.

Рекомендации проверяются на бэкенде, а не принимаются от модели на веру:
выдуманные `product_id` отбрасываются, цены и суммы считаются по каталогу,
продукты, которых нет в магазине, помечаются как внешние предложения, а
рекомендация, не прошедшая проверку, уходит в обычный сценарий эскалации
вместо показа покупателю.

## 7. Запуск локально

```bash
uvicorn app:app --reload --port 8000
```

Telegram не может напрямую обратиться к `localhost`; используйте туннель
(например, `ngrok http 8000`) и укажите `APP_URL` на URL туннеля, затем
выполните `scripts/set_webhook.py` (см. раздел 11). Либо отправьте пример
JSON-обновления Telegram напрямую на
`http://localhost:8000/api/telegram/webhook` с заголовком
`X-Telegram-Bot-Api-Secret-Token`, равным вашему `TELEGRAM_WEBHOOK_SECRET`,
для ручного тестирования без туннеля.

## 8. Тестирование локально

```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest -q
```

С отчётом о покрытии тестами:


Тесты используют изолированную SQLite-базу в памяти и фиктивные ("fake")

Постоянное правило тестирования для этого репозитория см. в

## 9. Деплой на Vercel

1. Запушьте этот репозиторий в GitHub/GitLab/Bitbucket и импортируйте его
   в Vercel, либо выполните `vercel` из корня проекта через Vercel CLI.
2. В **Project Settings -> Environment Variables** добавьте каждую
   переменную из `.env.example` для окружения Production (и Preview, если
   используете preview-деплои) — вставляйте реальные значения, никогда их
   не коммитьте.
3. Задеплойте. Vercel определяет `api/index.py` как Python
   (FastAPI)-serverless-функцию; `vercel.json` перенаправляет все пути на
   неё, поэтому `/`, `/health` и `/api/telegram/webhook` обслуживаются одним
   и тем же приложением.
4. Примените миграции базы данных к продакшен-базе (`alembic upgrade
   head`) со своей машины или из CI — Vercel не запускает миграции за вас.

## 10. Настройка продакшен-webhook

После деплоя, установив `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и
`APP_URL` в локальной оболочке (совпадающими со значениями в Vercel):

```bash
python scripts/set_webhook.py
```

Проверка:

```bash
python scripts/webhook_info.py
```

Чтобы удалить webhook (например, чтобы вернуться к ручному тестированию):

```bash
python scripts/delete_webhook.py
```

## 11. Захват роли администратора

Два варианта:

- **Автоматический**: установите `ADMIN_TELEGRAM_ID` (ваш числовой
  Telegram user ID, например от @userinfobot) в переменных окружения до
  первого деплоя/первого вызова webhook. Этот аккаунт автоматически
  устанавливается администратором, а `/claim` навсегда отключается.
- **Разовый, вручную**: установите `ADMIN_SETUP_SECRET` в длинное
  случайное значение (`python -c "import secrets;
  print(secrets.token_urlsafe(24))"`), задеплойте, затем отправьте боту
  сообщение `/claim <этот секрет>` с того Telegram-аккаунта, который
  должен стать администратором. Первый успешный запрос `/claim` навсегда
  регистрирует этот аккаунт, все последующие попытки `/claim` отклоняются
  — это реализовано через защиту от гонки на уровне уникального
  ограничения (constraint) в базе данных, поэтому это безопасно, даже если
  два человека попытаются "заклеймить" роль одновременно.

## 12. Ротация скомпрометированных ключей Telegram/OpenAI

- **Telegram**: напишите @BotFather -> `/revoke` (или `/token`) для вашего
  бота, чтобы аннулировать старый токен и получить новый. Обновите
  `TELEGRAM_BOT_TOKEN` в Vercel, передеплойте, затем заново выполните
  `scripts/set_webhook.py` (регистрация webhook привязана к токену).
- **OpenAI**: отзовите ключ в панели OpenAI, сгенерируйте новый, обновите
  `OPENAI_API_KEY` в Vercel, передеплойте. Дополнительных действий не
  требуется.
- **Секрет webhook**: сгенерируйте новый `TELEGRAM_WEBHOOK_SECRET`,
  обновите его в Vercel, передеплойте, затем заново выполните
  `scripts/set_webhook.py`, чтобы Telegram начал отправлять новый
  секретный заголовок.
- После ротации любого секрета убедитесь через `python
  scripts/webhook_info.py`, что нет незакрытых ошибок.

## 13. Устранение неполадок

- **Бот не отвечает**: проверьте `python scripts/webhook_info.py` на
  предмет `last_error_message`; убедитесь, что `APP_URL` совпадает с
  реальным URL вашего Vercel-деплоя и что webhook был установлен уже после
  последнего деплоя.
- **401 от эндпоинта webhook**: несовпадение `TELEGRAM_WEBHOOK_SECRET`
  между Vercel и тем, что было передано в `set_webhook.py` — значения
  должны быть идентичны.
- **`/health` возвращает `database: false`**: проверьте `DATABASE_URL` и
  убедитесь, что ваш провайдер Postgres разрешает подключения с исходящих
  IP-адресов Vercel (либо используйте пулер без IP-ограничений).
- **Дублирующиеся ответы на одно и то же сообщение**: проверьте, не
  зарегистрировано ли несколько webhook-ов (`webhook_info.py`), или что вы
  не развернули двух ботов на одном и том же токене.
- **Администратор не получает эскалации**: убедитесь, что администратор
  действительно зарегистрирован (`/stats` от имени администратора, либо
  проверьте таблицу `users` на наличие `role = 'admin'`); если его нет, все
  эскалации сохраняются со статусом `pending`, но не доставляются (это
  ожидаемое поведение — ничего не теряется).

## 14. Заметки по безопасности

- Ни один секрет никогда не зашит в код; все читаются из переменных
  окружения (`config.py`).
- Webhook проверяет заголовок Telegram
  `X-Telegram-Bot-Api-Secret-Token` прежде, чем делать что-либо ещё.
- Все админ-команды/callback-и заново проверяют Telegram ID вызывающего по
  базе данных (`role = 'admin'`) при каждом запросе — содержимому
  `callback_data` никогда не доверяют как доказательству привилегий.
- Регистрация первого администратора защищена уникальным ограничением
  (constraint) в базе данных (а не проверкой-с-последующей-записью), так
  что её нельзя "выиграть" дважды даже при параллельных запросах.
- Все исходящие сообщения Telegram отправляются без `parse_mode`, поэтому
  пользовательский контент (имена, вопросы, ответы администратора) не
  может внедрить Markdown/HTML-форматирование или ссылки.
- Весь доступ к SQL идёт через параметризованный построитель запросов
  SQLAlchemy — нигде в кодовой базе нет сырого SQL со строковой
  интерполяцией.
- Базовое ограничение частоты запросов (rate limiting) на пользователя и
  ограничение длины сообщений применяются до любого обращения к OpenAI.
- Логирование никогда не включает полные секреты, полные тела обновлений
  или полный текст сообщений клиента в логах ошибок — только ID и краткие
  причины.

## 15. Известные ограничения Vercel / serverless

- **Никакой фоновой работы после ответа.** Обработчик webhook дожидается
  завершения всей обработки (записи в БД, отправки в Telegram, вызовы
  OpenAI) перед ответом; на Vercel нет надёжной фоновой задачи или
  долгоживущего потока. Таймаут функции настраивается через `vercel.json`
  (`functions.api/index.py.maxDuration`) — увеличьте его, если позволяет
  ваш тарифный план и вызовы OpenAI/Telegram выполняются медленно.
- **Файловая система доступна только для чтения во время выполнения.**
  `data/business.md` упаковывается на этапе сборки; сохранить изменения в
  него из работающей функции невозможно. Чтобы менять содержимое без
  передеплоя, замените `KnowledgeService` на источник на основе базы
  данных или объектного хранилища. Именно поэтому `KnowledgeService`
  сделан как заменяемый компонент.
- **Нет памяти процесса между запросами.** Каждая часть состояния, которая
  должна пережить между обновлениями (шаг FSM, дедупликация `update_id`,
  счётчики rate-limit), хранится в Postgres, а не в глобальной переменной
  Python.
- **Холодный старт** добавляет задержку первому запросу после периода
  простоя; таймауты OpenAI/Telegram настроены с запасом
  (`OPENAI_TIMEOUT_SECONDS`, `TELEGRAM_TIMEOUT_SECONDS`), чтобы это
  переживать, но очень медленный холодный старт в сочетании с медленным
  ответом OpenAI всё же может упереться в `maxDuration` функции.
- **Ограничения на подключения.** Много параллельных serverless-вызовов
  каждый открывает короткое соединение с Postgres; используйте провайдера
  с поддержкой пулинга, иначе можно исчерпать `max_connections` базы
  данных под нагрузкой.

```
├── config.py                   Pydantic Settings (только переменные окружения)
├── bot/
│   ├── router.py                Диспетчеризация обновлений
│   ├── context.py                Общий контекст на запрос
│   ├── handlers/                 Логика команд/callback-ов: start / customer / admin
│   ├── keyboards/                 Построители инлайн-клавиатур
│   ├── middleware/                 Проверка прав администратора, rate limiting
│   └── states/                      Константы состояний FSM
├── services/
│   ├── openai_service.py           OpenAI Responses API + структурированный вывод
```
